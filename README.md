# 小知了厨房卫士后台（厨房AI安全提醒仪 · 多主机管理系统）

0 成本自建的后台：网页可见所有主机 ID 的运行状态；打开某主机的**开发者模式**才显示**实时**状态，平时显示**上次同步状态**；单设备后台可**测试每个传感器**、**故障检测并给出原因分析**、**远程升级固件（OTA）**、**修改播报语音与触发参数**。

配套提供：多主机模拟器（无硬件可完整演示）、ESP32-C3 固件接入示例、部署指南（含豆包云电脑 + Cloudflare Tunnel 外网访问）。

---

## 一、功能清单

| 功能 | 说明 |
|---|---|
| 设备总览 | 所有主机 ID：在线/离线、当前状态、电量、固件版本、最后同步时间 |
| 同步策略 | 常态低频心跳显示「最后同步 HH:mm」；安全事件始终即时上报 |
| 开发者模式 | 打开后主机切高频采样实时上报，后台 WebSocket 实时刷新；TTL 超时自动关闭恢复低功耗 |
| 传感器自检 | 逐项测试雷达/燃气/温湿度/声敏/光敏/电池，显示结果 |
| 故障分析 | 故障码 → 原因/可能原因/排查建议（内置规则引擎，可配免费大模型增强） |
| 远程 OTA | 下发固件 URL + 版本号，主机双分区升级后重启上报新版本 |
| 参数下发 | 点火窗口、泄漏确认时长、提醒间隔、阈值等远程下发（NVS 持久化） |
| 语音配置 | 泄漏/忘关火/低电/自检话术远程修改 |
| AI 与工作流 | 模型接入（OpenAI 兼容 API，可配 Key）＋ 8 步检测工作流可视化编辑、恢复默认、一键下发、试运行调试 |
| 事件记录 | 每台主机安全事件历史（即时上报） |

## 二、快速开始（本地运行，5 分钟）

需要 Node.js 16+（[nodejs.org](https://nodejs.org) 下载 LTS）。

```bash
# 1. 进入工程目录，安装依赖
cd kitchen-admin
npm install

# 2. 启动后台（默认 http://localhost:3000）
npm start

# 3. 另开一个终端，启动多主机模拟器（模拟 A001/A002/A003 三台主机）
npm run simulate

# 4. 浏览器打开 http://localhost:3000 即可看到设备列表与全部功能
#    健康检查：http://localhost:3000/api/health
```

模拟器默认连**公共测试 Broker** `broker.emqx.io:1883`，无需任何账号。开发者模式、自检、OTA、参数与语音下发均可在网页上直接操作。

模拟器参数：

```bash
npm run simulate -- --interval 30        # 心跳间隔秒数（默认 60）
npm run simulate -- --devices A001,A003  # 只模拟指定设备
npm run simulate -- --events             # 允许随机产生忘关火事件
```

**演示建议**：A002 注入燃气传感器故障（G1）、A003 注入低电（B1），用于查看故障原因分析。

## 三、部署到豆包云电脑（Windows）并外网访问

### 第 1 步：把工程放到云电脑

- 将 `kitchen-admin` 整个文件夹复制到豆包云电脑（如 `D:\kitchen-admin`）。

### 第 2 步：安装 Node.js

- 在云电脑浏览器打开 [nodejs.org](https://nodejs.org)，下载 **Windows LTS 版**，一路下一步安装。

### 第 3 步：安装依赖并启动

- 打开 PowerShell / CMD：

```powershell
cd D:\kitchen-admin
npm install
npm start
```

- 看到 `[HTTP] 后台网页已启动: http://localhost:3000` 即成功。
- 云电脑本地打开 `http://localhost:3000` 可验证。
- **注意：云电脑关机后台即停**。需要长期在线时保持云电脑开机，并确认套餐允许长期挂机（见部署说明末尾）。

### 第 4 步：外网访问（Cloudflare Tunnel，免费）

让手机/其他电脑也能访问后台：

1. 下载 Windows 版 cloudflared：[https://github.com/cloudflare/cloudflared/releases](https://github.com/cloudflare/cloudflared/releases)（选 `cloudflared-windows-amd64.exe`），改名 `cloudflared.exe` 放到 `D:\cloudflared\`。
2. 在 PowerShell 运行（快速隧道，免费、无需注册）：

```powershell
cd D:\cloudflared
.\cloudflared.exe tunnel --url http://localhost:3000
```

3. 等几秒，会输出一个公网网址：`https://xxxxxxxx.trycloudflare.com`，任何设备浏览器打开即可访问后台。

> 快速隧道的网址每次重启会变；想要固定网址，可在 Cloudflare 注册免费账号，用 `cloudflared tunnel create` 建命名隧道（需要把域名 DNS 托管到 Cloudflare，域名本身约 10~60 元/年，非必需）。

### 第 5 步（建议）：换私有 MQTT Broker

公共测试 Broker 任何人都能订阅你的 topic，仅适合测试。正式使用建议在云电脑自建 **Mosquitto**（Windows 原生支持）：

- 下载安装 [Mosquitto](https://mosquitto.org/download/)（Windows 安装包）。
- 启动服务后，配置 `config.js`：

```bash
set MQTT_URL=mqtt://localhost:1883
set MQTT_TOPIC_PREFIX=kitchen/
set MQTT_USER=你的用户名
set MQTT_PASS=你的密码
npm start
```

- 主机固件里 `MQTT_HOST` 改为云电脑地址（走 Cloudflare Tunnel TCP 或内网访问），并把 `MQTT_TOPIC_PREFIX` 保持一致。

## 四、MQTT 协议（与固件对接）

Topic 前缀默认 `dev/`，可配置。设备 ID 建议 `字母+数字`，长度 ≤32。

| 方向 | Topic | 内容 |
|---|---|---|
| 主机 → 云 | `dev/{id}/status` | 心跳/状态快照（JSON，常态 60s，开发者模式 5s） |
| 主机 → 云 | `dev/{id}/event` | 安全事件（泄漏/忘关火等，**即时**上报） |
| 主机 → 云 | `dev/{id}/diag` | 传感器自检结果 |
| 主机 → 云 | `dev/{id}/snap` | 场景快照（触发后台 AI/规则场景判断） |
| 云 → 主机 | `dev/{id}/ai` | 场景判定结果（source=rule/ai，cooking 布尔 + 置信度 + 原因） |
| 云 → 主机 | `dev/{id}/cmd` | 指令：devmode / diag / ota / set_params / set_voice / set_workflow |

**status 示例**：

```json
{"id":"A001","ts":1793445083345,"state":"idle","battery":97,"fw":"1.2.0","devmode":false,"sensors":{"radar":{"presence":true,"dist":90},"mq":170,"sht":{"t":26.5,"h":58},"mic":0,"light":340}}
```

**diag 示例**（items 里 status 为 `err`/`warn` 的项携带故障码）：

```json
{"id":"A002","ts":...,"seq":123,"items":[{"name":"mq","status":"err","code":"G1","value":4095,"detail":"ADC 满量程，疑似信号开路"}]}
```

**cmd 示例**：

```json
{"cmd":"devmode","on":true,"ttl":1800}
{"cmd":"diag","seq":123}
{"cmd":"ota","url":"https://your-server/fw.bin","version":"1.3.0"}
{"cmd":"set_params","params":{"fire_detect_window":45,"remind_interval_sec":240}}
{"cmd":"set_voice","voice":{"gas_leak":"检测到燃气泄漏，请立即开窗通风"}}
{"cmd":"set_workflow","version":2,"workflow":[...8个步骤...],"ai":{"enabled":false,"endpoint":"","apiKey":"","model":"","timeoutSec":8}}
```

**snap 示例（主机 → 云，触发后台场景判定）**：

```json
{"id":"A001","ts":...,"seq":123,"sensors":{"radar":{"presence":true,"dist":80},"mq":3800,"sht":{"t":26.5,"h":58},"mic":0,"light":340},"personPresent":false,"cooking":true,"sinceCookStartSec":420}
```

**ai 示例（云 → 主机，场景判定结果）**：

```json
{"id":"A001","ts":...,"source":"rule","cooking":true,"confidence":0.6,"reason":"本地规则引擎判定（未配置大模型 Key）"}
```

## 五、故障码表（后台原因分析规则）

| 码 | 传感器 | 判定 | 主要原因与排查 |
|---|---|---|---|
| R1 | 雷达 LD2410C | UART 无响应 | 接线/分压/供电 → 查 GPIO4/5 |
| G1 | 燃气 MQ | ADC 满量程≈4095 | AO 开路/分压断 → 查 GPIO3 链路 |
| G2 | 燃气 MQ | 读数不稳定 | 预热不足/老化/5V 抖动 |
| T1 | 温湿度 SHT3X | I2C 无应答 | 接线/4.7k 上拉 → 查 GPIO6/7 |
| M1 | 声敏 | 无信号 | 接线/灵敏度 → 查 GPIO11 |
| L1 | 光敏 | 读数恒 0/满量程 | 分压/遮挡 → 查 GPIO1 |
| B1 | 电池 | <3.4V | 亏电，立即充电 |
| B2 | 电池 | 采样恒 0/满量程 | 10k/10k 分压断 → 查 GPIO0 |
| S1 | 功放 | I2S 无输出 | 喇叭/供电/SD 使能 → 查 GPIO12-15 |

可选：在 `config.js` 配置免费大模型 API（`AI_API_KEY`/`AI_ENDPOINT`/`AI_MODEL`，OpenAI 兼容接口，如硅基流动/DeepSeek/阿里百炼），自检发现故障时后台自动追加 AI 综合分析。

## 六、ESP32-C3 固件接入

`firmware/esp32_backend_demo/esp32_backend_demo.ino` 是可编译的接入示例：

- 修改 `WIFI_SSID`/`WIFI_PASS`/`MQTT_HOST`/`DEVICE_ID` 后烧录；
- 已实现：心跳/状态上报、事件上报、自检上报、开发者模式切换、参数与语音下发（NVS 持久化）、OTA 指令处理；
- 接入主固件时，把 `collectSensors()` 换成 V46 定稿 GPIO 的真实传感器读取，把 `diag` 各 items 换成真实健康判定即可。

## 七、AI 与工作流（模型接入 + 检测链路可视化配置）

后台「AI 与工作流」页签把**模型接入**与**检测链路**全部搬进网页，支持一键修改、调试、下发：

### 7.1 AI 模型配置

- 主机 ESP32 内存小、跑不动大模型：检测到可疑场景时**上传传感器快照（snap）**，由后台调用所配大模型判断「是否厨房使用场景」，结果回发主机。
- 接口为 **OpenAI 兼容**（DeepSeek / 硅基流动 / 阿里百炼等均可），后台只需填写 `endpoint / apiKey / model / temperature / timeoutSec`，一键保存。
- **不填 Key = 0 成本模式**：自动用内置本地规则引擎兜底（source=rule），功能完整可用。

### 7.2 检测工作流（8 步，可独立启停与调参）

| 步骤 | 角色 | 作用 |
|---|---|---|
| scene 场景触发判定 | trigger | 人体→光线→温度依次确认，全部符合才进入燃气检测 |
| ignite 点火尖峰检测 | trigger | 点火瞬间变化率超 5σ（60s 窗口）并回落确认 |
| leak 燃气泄漏确认 | trigger | 仅非做饭态，MQ 超阈值持续 3~5 分钟才报泄漏 |
| steam 蒸汽排除 | exclude | 湿度骤升判为蒸汽（电水壶/高压锅），排除泄漏误报 |
| stove_timeout 防忘关火（P0） | trigger | 做饭态 + 人离开：超时首次提醒、之后按间隔循环 |
| pet 宠物排除 | exclude | 15 分钟人类特征确认，宠物进厨房不触发 |
| temp_fallback 温度兜底 | fallback | 仅非做饭态，温度异常攀升兜底告警 |
| baseline 每日基线档案 | fallback | 每日未开火空闲自动建档（24h 双基线） |

- 每个步骤可**开关**、可改参数（阈值/窗口/间隔等），保存后版本 +1；
- **一键下发**到当前主机（NVS 持久化），主机按新链路执行；
- **恢复默认**随时还原出厂工作流；
- **试运行调试**：粘贴传感器快照 + 场景上下文，本地立即跑一遍当前工作流，逐步显示每步结果与最终判定等级（low/medium/high + 告警列表 + 下一步动作），无需真机即可验证逻辑。

## 十、部署到豆包云电脑的注意点（重要）

1. **云电脑关机 = 后台停**：后台是常驻服务，云电脑关机后主机状态无法上报。需要长期 7×24 在线时，保持云电脑开机，并确认套餐允许长期挂机（官方说明：云电脑任务在云端持续运行、不依赖本机；长时间任务会消耗订阅额度，具体时长限制请通过「设置 → 帮助与反馈 → 在线咨询」向官方确认）。
2. **公共 Broker 仅限测试**：正式使用换私有 Mosquitto（见第 5 步）。
3. **设备数量**：JSON 文件存储适合个人规模（几十台内）；设备更多时可平滑迁移到 SQLite。
4. **设备注册语义**：首次启动自动预置 `A001,A002,A003`（可用环境变量 `INITIAL_DEVICES` 覆盖）；后台添加的设备才有 ID；MQTT 上报只接受已注册设备，删除后不自动复活。
5. **真机烧录（WebSerial）**：需桌面 Chrome/Edge 89+、HTTPS 页面（trycloudflare 隧道满足）、电脑 USB 连接 ESP32-C3；豆包 App 内浏览器不支持 WebSerial，请用电脑浏览器打开公网链接操作。烧录使用**合并后的整片固件**（Arduino 导出 merged bin / ESP-IDF `esptool merge_bin`），起始地址 0x00000。烧录中断不会损坏芯片，重新连接再烧即可恢复。
6. **工作流推送语义（v2.1）**：保存工作流只升版本号、**不自动下发**，需点击「AI 与工作流 → 推送到全部设备」才生效（避免误改误发）；离线错过推送的设备，后台会在其下次心跳时**自动补发**最新工作流（设备需在 status 上报 `workflow_version`，固件示例已支持）。设备卡片/详情页会显示工作流版本与“落后”标记。
7. **AI 配置统一**：自检故障 AI 增强与场景 AI 判断共用「AI 与工作流」页的同一份 AI 配置（settings.ai），一处修改全局生效。

## 十一、真机烧录操作（网页直连）

1. 电脑 Chrome/Edge 打开后台公网链接 →「程序烧录」。
2. 先在固件库上传编译好的 `.bin` 合并固件（或使用仓库 `firmware/esp32_backend_demo` 在 Arduino IDE 导出）。
3. USB 连接 ESP32-C3 开发板，点击「连接设备」，在弹出的系统窗口选择串口。
4. 选择固件与 Flash 容量（ESP32-C3 一般 4MB），点击「开始烧录」。
5. 日志区显示：连接芯片 → 擦除 → 写入 → 硬复位；完成后主机重启并自动上报状态。
6. 给主机配网：进「全部设备 → 该设备 → WiFi 配置」填 SSID/密码下发；或烧录前在固件里改 `WIFI_SSID/WIFI_PASS` 常量。

## 十二、有线调试（USB 直连电脑，真实测试/查故障/烧录/版本重置）

**本质**：不是网页模拟——浏览器通过 WebSerial 直连主机 USB 串口，按「有线调试协议」真实读写主机（数据全部来自真机串口，不经过服务器）。固件端实现在 `firmware/esp32_backend_demo/esp32_backend_demo.ino`。

**使用步骤**：电脑 Chrome/Edge 打开后台 →「有线调试」→「连接 USB」→ 系统弹窗选择主机串口（115200）→ 自动检测链路（已打开→探测主机应答→成功/真实报错），随后自动读取设备详情/运行状态，开启 2s 实时传感器轮询；可执行真机自检、单项测试、参数/语音/音量/工作流/WiFi USB 直写、事件日志读取、软重启、恢复出厂、调试终端。

**连接检测与报错**：未选设备（取消）→ 提示未选择串口；打开失败 → 按错误分类提示（安全限制/串口被占用/已打开/设备不存在）；已打开但无应答 → 提示可能选错串口、固件无 DBG 协议或波特率不符；USB 拔出/关闭 → 实时提示断开。数据全部来自真机串口。

**协议（串口 115200 8N1，行分隔，请求 `DBG:<cmd> [arg]`，应答单行 JSON）**：

| 命令 | 作用 | 关键应答字段 |
|---|---|---|
| `DBG:ping` | 链路探测 | pong, ts |
| `DBG:info` | 设备详情 | id, fw, chip, uptimeSec, freeHeap, workflowVersion, volume, wifiSsid, params |
| `DBG:sensors` | 实时传感器读数（真机采集） | sensors{radar,mq,sht,mic,light,battery,voltage} |
| `DBG:status` | 状态机快照 | state, devmode, cooking, lastEvent, workflow |
| `DBG:diag` | 逐项真机自检（**全部 8 项**：雷达/燃气/温湿度/声敏/光敏/电池/LED/喇叭） | items[{name,status,code,value}]（故障码对应第五章码表，前端同源内置） |
| `DBG:test <目标>` | 单项真机测试（radar/mq/sht/mic/light/battery/led/speaker） | target, value, status（led 亮红绿蓝灭；speaker 播 1kHz 音） |
| `DBG:get <key>` | 读配置（params/voice/workflow/volume/wifi） | key, value |
| `DBG:set <key> <json>` | 写配置（volume/params/voice/workflow，NVS 持久化） | key, value |
| `DBG:wifi <ssid> <pass>` | 保存 WiFi 并重连（USB 直写，等效远程 set_wifi） | ssid, connected |
| `DBG:event <n>` | 主机本地事件缓冲（最近 n 条，最多 20） | events[] |
| `DBG:reboot` | 软重启主机（保留全部配置） | action |
| `DBG:reset` | 版本重置：清 NVS（参数/语音/工作流/音量/WiFi）→ 重启 | action |

**协议契约自动化测试**：`node tools/dbg_protocol_test.js`（25 项断言：各命令应答结构、音量越界钳制、单项测试、工作流版本读写、WiFi 直写、reboot/reset、未知命令拒绝）。
